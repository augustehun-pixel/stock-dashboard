# 골든크로스 기준 "확정된 가장 최근 고점" 규칙 조사 — 진행 상태

이 문서는 다음 세션에서 이어서 작업할 수 있도록 현재까지의 조사 상태를 기록한 것이다.
**아직 규칙을 최종 확정하지 않았고, 이 분석 결과를 실제 매매 규칙 코드로 구현하지도 않았다.**
지금까지의 모든 검증은 `server/*.js`의 기존 함수를 재사용하는 임시(scratchpad) 스크립트로만 진행했고,
`server/` 코드 자체에는 아직 "확정된 가장 최근 고점" 판정 로직이 들어가 있지 않다.

## 우리가 만들고 있는 규칙의 목적

향후 피보나치 되돌림 등에 쓸 매매 규칙의 기준점 두 개를 정하는 것이 목적이다:

```
기준 저점 → 확정된 가장 최근 고점 → 골든크로스
```

- 피보나치 시작점(1) = 기준 저점
- 피보나치 종료점(0) = 확정된 가장 최근 고점

"확정된 가장 최근 고점"의 정확한 수학적 정의(N봉, fractal, ZigZag, % 하락 등)는 **아직 결정하지 않았다**.
지금은 실제 여러 종목의 골든크로스 사례를 모아서, 공통으로 나타나는 가격 구조를 관찰하는 단계다.

## 확정된 규칙 (변하지 않는 전제)

1. **골든크로스는 반드시 일봉 기준으로 판정한다.** 4시간마다가 아니라 거래일당 1번만 판정.
   - 전 거래일: 4시간봉 MA200 ≤ 일봉 MA200
   - 당일: 4시간봉 MA200 > 일봉 MA200
   - 4시간봉 MA200은 그 거래일의 오후(PM, 13:00~15:30) 세션 확정값만 사용 (오전 세션 사용 금지)
2. **골든크로스 이전 데이터만 사용한다.** 골든크로스 당일과 그 이후 데이터는 고점/저점 확정 과정에 **절대** 사용하지 않는다 (look-ahead 금지).
3. **기준 저점**: 골든크로스 이전 전체 구간에서 일봉 lowPrice가 가장 낮은 날.
4. **확정된 가장 최근 고점**은 반드시:
   - 기준 저점보다 나중, 골든크로스보다 이전에 위치해야 한다.
   - 골든크로스가 "발생한 시점에 이미" 고점으로 확인 가능했어야 한다 (다음날 데이터로 미래를 미리 보고 고점을 정하면 안 됨).
5. 시간 순서는 반드시 `기준 저점 → 확정된 가장 최근 고점 → 골든크로스`. `기준 저점 → 골든크로스 → 고점` 순서는 금지.

## 지금까지 탐색용으로 써본 방법 (아직 최종 채택 아님)

- "봉우리" = 전날/다음날 고가보다 오늘 고가가 더 높은 날 (가장 단순한 로컬 피크, N봉/fractal 같은 정식 정의 아님).
- 이 방법의 구조적 한계: 골든크로스 바로 전날은 "다음날" 데이터가 골든크로스 당일이라 원칙적으로 판정 불가 → 그 경우는 후보에서 자동 제외됨 (HPSP 2025-10-14 사례에서 확인).
- 후보들 중 골든크로스에 가장 가까운(마지막) 봉우리를 "확정된 최근 고점 후보"로 놓고, 그 이후 며칠간 하락이 확인됐는지 관찰.

## 재사용 가능한 스크립트 로직 (scratchpad, server/*.js에는 없음)

로컬 피크(봉우리) 후보 탐색과 하락 확인은 `server/swingLevels.js`가 아니라 scratchpad 스크립트에서만 계산했다(정의가 아직 미확정이므로 서버 코드에 넣지 않음). 핵심 로직:

```js
// 봉우리 = 전날/다음날 고가보다 오늘 고가가 더 높은 날.
// 탐색 구간: 기준 저점(exclusive) ~ 골든크로스(exclusive).
// look-ahead 금지: "다음날"이 골든크로스 당일 이상이면 그 날은 후보에서 제외.
function findLocalPeakCandidates(dailySeries, referenceLowDate, goldenCrossDate) {
  const candidates = []
  for (let i = 1; i < dailySeries.length - 1; i++) {
    const day = dailySeries[i], prev = dailySeries[i - 1], next = dailySeries[i + 1]
    if (day.date <= referenceLowDate) continue
    if (day.date >= goldenCrossDate) continue
    if (next.date >= goldenCrossDate) continue
    if (day.high > prev.high && day.high > next.high) candidates.push({ date: day.date, high: day.high })
  }
  return candidates
}
// "확정 고점 후보" = candidates.at(-1) (골든크로스에 가장 가까운 봉우리)
```

`getDailyMA200Series(code)`로 얻은 dailySeries와 `getCrossoverAnalysis(code)`의 `referenceLow`/`latestGolden`을 그대로 넣어 쓰면 된다.

## 주의 사항 (계속 유지)

- `.env`, TOSS_CLIENT_KEY/SECRET, access token은 어떤 기록/로그/캐시에도 절대 남기지 않는다.
- `server/.cache/`는 `.gitignore`에 등록되어 있어 커밋되지 않는다.
- look-ahead 금지: 어떤 저점/고점 계산도 골든크로스 당일 및 이후 날짜 데이터를 사용해서는 안 된다.
