# 돌파매매 - Claude 규칙

## 1. 목적

우상향하는 고점 추세선을 가격이 강한 거래량과 함께 돌파했을 때 진입한다.

상승을 미리 예상하여 진입하지 않는다.
실제 돌파가 확인된 이후에만 진입한다.

이 전략은 시장을 예측해서 미리 진입하는 전략이 아니다.
유효한 H1-L-H2 구조가 만들어진 후에도 진입하지 않고, 실제 돌파가 확인되었을 때만 진입한다.
("낚시꾼처럼 조건이 올 때까지 기다리는 방식")

앱은 미래 가격을 예상하거나, 매매 기회를 만들기 위해
과거 차트에서 억지로 유효한 구조를 찾아내지 않는다.

---

## 2. 가격 구조

기본 가격 흐름은 다음과 같다.

```
상승 → H1 → 눌림 → L → 다시 상승 → H2
```

1. 상승 흐름에서 H1이 형성된다.
2. H1 이후 눌림(조정)이 발생한다.
3. 눌림 구간 전체에서 가장 낮은 지점이 기준점(L)이다.
4. 가격이 다시 상승하며 H2 후보가 나타난다.
5. H2 후보가 필수 조건(4·5절)을 만족하면 최종 H2로 확정된다.
6. H1과 최종 H2를 연결하여 우상향 고점 추세선을 만든다.

이 구조는 현재 차트에서 가장 최근에 형성되는 흐름을 기준으로 판단한다.
과거 차트에서 조건에 맞는 H1-H2 쌍을 찾아서 억지로 매매 기회를 만들지 않는다(9절).

---

## 3. H1 정의

H1은 다음과 같이 정의한다.

> 최근 가격 흐름에서 상승 후 눌림이 시작되기 직전의 고점

H1을 찾기 위해 다음과 같은 조건을 임의로 추가하지 않는다.

- fractal high
- 좌우 N개 캔들보다 높아야 한다는 조건
- H1 이후 N개 봉을 기다리는 조건
- 특정 % 이상 하락해야 눌림이라는 조건
- 특정 ATR 이상 조정
- 특정 캔들 개수의 조정
- 임의의 swing-high 알고리즘

핵심은 "상승 후 눌림이 시작되기 직전의 고점"이라는 가격 흐름 그 자체이며,
그 외의 수치 기준을 별도로 만들지 않는다.

### H1 자동 탐지 기준 (2026-09-05 확정)

"상승 후 눌림이 시작되기 직전의 고점"을 코드가 판정할 수 있도록 다음 기준을 사용한다.

```
next.high < current.high
→ current candle = H1
```

바로 다음 1개 캔들의 high가 현재 캔들의 high보다 낮아지면, 현재 캔들을 H1으로 확정한다.

이 기준은 위에서 금지한 fractal / pivot / 좌우 N봉 비교가 아니다. 좌우 여러 봉을 비교하지
않고 오직 바로 다음 1개 캔들만 확인하며, 이를 통해 1봉 눌림도 H1으로 인정한다. 위에서 금지한
다음 항목들은 그대로 유지된다: fractal, pivot, 좌우 N봉, 특정 % 조정, ATR, 특정 조정 캔들 수.

예:

```
100
103
107
110  ← H1 (다음 봉 109가 110보다 낮음)
109  ← 눌림 시작
```

반대로 다음 봉이 더 높으면(아직 상승 중이면) H1으로 확정하지 않는다:

```
100
103
107
110
112  ← 아직 상승 중, 110은 H1으로 확정하지 않는다
```

`next.high === current.high`(동일)인 경우도 "낮아진 것"이 아니므로 H1으로 확정하지 않는다.
반드시 `next.high < current.high`로 엄격히 낮아야 한다.

**look-ahead 금지**: H1은 다음 캔들이 실제로 형성된 이후에만 확정할 수 있다. 현재 캔들이 아직
가장 최근 캔들이고 다음 캔들이 존재하지 않으면, 그 캔들을 미리 H1으로 확정하지 않는다. 다음
캔들의 high가 실제 데이터로 들어와 `next.high < current.high`가 확인된 시점에만 H1이
확정된다. 아직 존재하지 않는 미래 캔들을 예측하거나 참조하지 않는다.

### 가격(price) 필드

H1과 H2는 모두 "고점"이므로, 가격 비교와 추세선 연결에는 각 캔들의 **high** 값을 사용한다.

```
price(H1) = H1 candle.high
price(H2) = H2 candle.high
```

몸통(open/close)은 H1/H2의 가격으로 사용하지 않는다. 몸통은 10·12절의 돌파 판정(추세선을
완전히 넘어 마감했는지)에만 쓰인다.

---

## 4. H2 정의 및 확정 조건

H1 이후 눌림이 발생하고 가격이 다시 상승할 때 H2 후보를 관찰한다.

H2는 가격만으로 결정하지 않는다. H2로 확정되려면 다음 두 조건을
**동시에(AND)** 만족해야 한다(price 필드 정의는 3절 "가격(price) 필드" 참고 - H1/H2 모두
candle.high 사용).

필수 조건:

```
price(H2) > price(H1)
AND
Volume(H2) > Volume(H1)
```

가격 조건과 거래량 조건은 OR 관계가 아니라 반드시 AND 관계다.

예:

```
H1: price = 100, volume = 1000

candidate A: price = 103, volume = 700
→ 103 > 100 이지만 700 < 1000 → H2 아님

candidate B: price = 108, volume = 1500
→ 108 > 100 AND 1500 > 1000 → H2 조건 충족
```

### 중간 고점 처리

가격은 H1보다 높지만 거래량 조건을 만족하지 못하는 고점(위 candidate A)은
H2로 확정하지 않는다. 이 경우:

- H1을 변경하지 않는다.
- 구조를 처음부터 다시 시작하지 않는다.
- L 계산 구간을 리셋하지 않는다.
- 이후 캔들에서 H2 조건(가격+거래량)을 만족하는 고점이 나타나는지 계속 관찰한다.

두 조건을 모두 만족하는 첫 번째 고점이 나타나면 그 고점을 최종 H2로 확정한다.
단, 최종 H2도 6절의 100캔들 제한을 만족해야 한다.

---

## 5. 기준점 L

L은 다음과 같이 정의한다.

```
L = lowest low between H1 and final H2
```

H1 이후부터 최종 H2가 형성되기 전까지 전체 구간에서
가장 낮은 저가(low) 하나를 L로 사용한다.

L은 다음일 필요가 없다.

- fractal low
- swing low
- 첫 번째 눌림 저점
- 가장 최근 눌림 저점

중간에 H2 조건을 만족하지 못한 고점(4절의 candidate A 같은 경우)이 있었다고 해서
L 계산 구간을 다시 시작하지 않는다. H1~최종 H2 전체 구간을 그대로 사용한다.

H2가 만들어진 이후(대기 중)에도 가격은 L 아래로 내려가면 안 된다.
L이 무너지면 기존 구조는 무효로 판단한다(8절).

---

## 6. 시간축 (100캔들 규칙)

H1과 최종 H2 사이의 거리는 현재 사용자가 보고 있는 타임프레임 기준
100개 캔들 이내여야 한다.

필수 조건:

```
distance(H1, final H2) <= 100 candles
```

100캔들 초과 시:

```
STRUCTURE INVALID
```

이 규칙과 관련해 다음 원칙을 반드시 지킨다.

- 100캔들을 초과했다고 해서 과거의 다른 H1을 찾아 조건을 맞추지 않는다.
- 100캔들을 초과했다고 해서 앱이 자동으로 상위 타임프레임으로 변경하거나
  그 타임프레임에서 새로운 구조를 재탐색하지 않는다.
- 현재 타임프레임에서는 그대로 INVALID로 판단한다.
- 상위 타임프레임을 확인할지는 사용자가 직접 결정한다.

**중요**: 이 100캔들 제한은 오직 H1~H2 사이의 거리에만 적용한다.
H2가 형성된 이후 돌파를 기다리는 시간에는 이 제한을 적용하지 않는다(7절).

---

## 7. H2 이후 행동과 대기시간

유효한 H1-L-H2 구조가 완성되어도 즉시 진입하지 않는다.

H2가 형성되면 H1과 H2를 연결한 우상향 고점 추세선을 사용하고,
시장 방향을 예측해서 미리 진입하지 않으며, 실제로 추세선을 돌파할 때까지 기다린다.

H2 이후 돌파를 기다리는 데 캔들 개수 제한을 두지 않는다
(예: 10/20/50/100캔들 이내 같은 임의의 시간 제한을 만들지 않는다).
유효한 구조가 유지되는 동안(=L이 무너지지 않는 동안) 실제 돌파가 발생할 때까지 기다린다.

---

## 8. 대기 중 구조 무효화

H2 이후 추세선 돌파를 기다리는 동안 다음 조건이 발생하면 구조가 무효가 된다.

필수 조건:

```
price < L
→ STRUCTURE INVALID
```

이 경우:

- 기존 H1-H2 추세선을 더 이상 진입 근거로 사용하지 않는다.
- 해당 구조의 돌파 진입을 더 이상 기다리지 않는다.
- 과거 H1/H2 구조로 되돌아가 다른 돌파 신호를 찾지 않는다.
- 이후 새로운 가격 구조(새 H1부터)가 만들어질 때까지 기다린다.

---

## 9. 최근 구조 우선 원칙

항상 현재 차트에서 가장 최근에 형성된 H1 → 눌림 → H2 구조를 평가한다.

현재 구조가 다음 중 하나라도 해당하면:

- H2 <= H1
- Volume(H2) <= Volume(H1)
- distance(H1, H2) > 100
- (대기 중) price < L

```
CURRENT STRUCTURE = INVALID
→ NO ENTRY
```

이 경우 더 과거의 고점들을 다시 조합하여 유효한 H1-H2 쌍을 찾지 않는다.
새로운 가격 구조가 만들어질 때까지 기다린다.

앱은 매매 기회를 만들기 위해 과거 구조를 억지로 검색해서는 안 된다.

---

## 10. 돌파

H1과 최종 H2를 연결한 우상향 고점 추세선을 사용한다.

가격이 이 추세선을 돌파해야 한다.

단순히 꼬리가 추세선을 넘어가는 것은 돌파로 인정하지 않는다.

돌파봉이 완전히 마감된 이후에만 돌파를 판단한다(봉이 마감되기 전에는 확정하지 않는다).

---

## 11. 돌파 거래량

실제로 추세선을 돌파하는 봉의 거래량을 확인한다.

필수 조건:

```
Volume(H1) < Volume(H2) < Volume(Breakout)
```

즉 거래량은 다음 순서로 단계적으로 증가해야 한다.

```
첫 번째 고점(H1) → 두 번째 고점(H2) → 추세선 돌파봉(Breakout)
```

---

## 12. 유효 돌파

돌파봉의 몸통이 고점 추세선 위에서 마감되어야 한다.

```
min(open, close) > trendline value  (돌파봉 몸통이 추세선 위에서 마감)
```

- 꼬리만 추세선을 넘어간 경우: INVALID
- 몸통이 다시 추세선 아래에서 마감한 경우: INVALID
- 돌파봉 몸통이 추세선 위에서 마감한 경우: VALID

봉이 완전히 마감되기 전에는 돌파를 확정하지 않는다.

---

## 13. 진입 조건 (ENTRY)

다음 조건을 모두 충족해야 진입할 수 있다.

- H2 > H1
- Volume(H2) > Volume(H1)
- H1-H2 추세선이 우상향한다.
- H1 이후 만들어진 기준점 L이 유지된다(무너지지 않는다).
- H1과 최종 H2가 100캔들 이내에 있다.
- 가격이 H1-H2 고점 추세선을 돌파한다.
- 돌파봉이 완전히 마감된다.
- 돌파봉 몸통이 추세선 위에서 마감한다.
- Volume(Breakout) > Volume(H2)

판정:

```
ALL CONDITIONS TRUE → ENTRY VALID
하나라도 FALSE → NO ENTRY
```

별도의 추세선 리테스트는 필수 조건이 아니다.

단, 돌파봉이 마감되기 전에는 절대 진입하지 않는다.

---

## 14. 손절 (STOP LOSS)

진입 이후 가격이 다시 고점 추세선 아래로 내려오고,
캔들 몸통이 추세선 아래에서 마감하면 손절한다.

조건:

```
Candle body closes below breakout trendline
→ EXIT / STOP LOSS
```

꼬리만 추세선 아래로 내려간 것은 이 조건만으로 손절로 판단하지 않는다.

진입 근거였던 추세선 돌파가 무효화되면 포지션을 유지하지 않는다.

---

## 15. 익절 (TAKE PROFIT)

익절 목표를 판단할 때 이전 차트에서 만들어진 의미 있는 고점을 참고 개념으로 확인한다.

반드시 전체 차트의 절대적인 최고점일 필요는 없다.

다음과 같은 고점을 익절 기준으로 사용할 수 있다.

- 과거 가격 움직임에서 만들어진 의미 있는 고점
- 기술적 반등 과정에서 만들어진 중간 고점

### V1 익절 정책: MANUAL

위 "의미 있는 고점" 기준은 아직 자동 계산 규칙으로 충분히 정의되지 않았다.
따라서 V1에서는 다음과 같이 처리한다.

```
TAKE_PROFIT_V1 = MANUAL
```

- 앱은 자동으로 익절 가격을 계산하지 않는다.
- ENTRY VALID 판정에는 익절 조건이 포함되지 않는다(13절 진입 조건과 무관).
- 사용자가 차트를 보고 직접 익절 목표를 판단한다.
- 향후 별도의 익절 규칙이 충분히 정의되면 그때 자동화할 수 있다.

---

## 핵심 판정 로직

```
STRUCTURE_VALID =
  H2 > H1
  AND Volume(H2) > Volume(H1)
  AND distance(H1, final_H2) <= 100 candles
  AND trendline_slope(H1, H2) > 0
  AND L_is_maintained   // price >= L, 대기 중 하회 시 false

VOLUME_VALID =
  Volume(H1) < Volume(H2) < Volume(Breakout)

BREAKOUT_VALID =
  price_breaks_trendline
  AND breakout_candle_is_fully_closed
  AND breakout_candle_body_closes_above_trendline

ENTRY_VALID =
  STRUCTURE_VALID
  AND VOLUME_VALID
  AND BREAKOUT_VALID

STOP_LOSS =
  after_entry
  AND candle_body_closes_below_trendline

TAKE_PROFIT_V1 = MANUAL   // 자동 계산 없음, 사용자가 직접 판단
```
